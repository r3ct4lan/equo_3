# Проверка отсутствия скрытых зависимостей Should/Later

Дата: 2026-10-15. Базовый snapshot: `ba14ff2` (`main`, DR-E7-055).
Итог: **PASS** — открытых обязательных зависимостей от `Should have`, `Later`
или `Out of scope` в основном пользовательском пути не обнаружено.

## Область проверки

Сверены основной путь и каталог сценариев в разделах 6, 8 и 14
[`mvp-scope.md`](../mvp-scope.md), допустимые временные процессы раздела 15,
реальные HTTP routes, страницы интерфейса и существующие browser acceptance.
Проверка касается зависимости, необходимой для полного результата, а не
наличия общего кода или нормативного контракта для будущего сценария.

| Категория | Сценарии | Сверка с реализацией и основным путём | Результат |
|---|---|---|---|
| Should | `MVP-SC-006` — профиль и смена email | `GET /api/v1/me` доступен для чтения; `PATCH /me` и email-change routes отсутствуют. Имя/email не меняются в основном пути. | Нет скрытой зависимости |
| Should | `MVP-SC-007` — деактивация/реактивация | Endpoint деактивации отсутствует. Активация и повторная отправка ссылки используются для обязательной первичной регистрации (`SC-001`); это не требует добровольной деактивации и возврата. | Нет скрытой зависимости |
| Should | `MVP-SC-014` — удаление долга | У `DebtController` есть create/update/list/detail, но нет `DELETE`; основной путь создаёт и читает активный долг. | Нет скрытой зависимости |
| Should | `MVP-SC-017` — исправление/удаление `MANUAL` | `TransferController` публикует create/detail/history, но не `PUT/DELETE`; UI не показывает редактор или удаление. Созданного `MANUAL` достаточно для основного результата. | Нет скрытой зависимости |
| Later | `MVP-SC-010` — Connect из общего долга | Прямой `POST /api/v1/connects` отсутствует. Основной путь использует приглашение; допустимое создание долга может создать Connect согласно разделу 15. | Нет скрытой зависимости |
| Later | `MVP-SC-018` — связь возврата с долей | В создании `MANUAL` `relatedTransferId` не задаётся, изменение ссылки не экспонируется; acceptance SC-016 фиксирует `related` links как `null`. | Нет скрытой зависимости |
| Out of scope | `MVP-SC-023—029` | Просмотренные HTTP routes и пользовательские страницы не требуют импорта/экспорта, admin-панели, расширенной модели расходов, погашения, общего поиска/жизненного цикла Connect, архива или финансовых уведомлений. | Не входят в путь |

## Доказательства основного пути

- [`mvp-scope.md`, раздел 6](../mvp-scope.md#6-основной-пользовательский-путь) связывает регистрацию, login, invitation/Connect, долг, чтение баланса/истории и `MANUAL` только с обязательными сценариями и зависимостями `SC-019—021`.
- [Приёмка SC-016](manual-transfer.md) подтверждает полный browser journey двух пользователей: регистрация и активация, login, invitation/Connect, расход, `MANUAL`, баланс и история у обеих сторон. Она также подтверждает отсутствие edit/delete controls и `relatedTransferId` у `MANUAL`.
- [Приёмка SC-013](update-debt.md) подтверждает, что изменение активного долга выполняется отдельным обязательным сценарием; мягкое удаление не нужно для корректировки.
- Фактические route declarations проверены в `MeController`, `DebtController`, `TransferController`, `ConnectController`, identity и invitation controllers. Нереализованные Should/Later endpoints не представлены placeholder routes.

## Вывод и границы

DR-E7-056 закрывает только аудит зависимости. Он не реализует Should/Later и не
переклассифицирует их; определения и правила раздела 15 `mvp-scope.md`
достаточны, менять нормативные документы не потребовалось. Технические
доказательства основного пути не подтверждают production deployment, внешнюю
staging SMTP доставку или решение Product Owner; эти release вопросы остаются
открытыми по DR-E7-054/058.
