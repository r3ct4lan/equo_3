# Продуктовый контекст Equo

Актуально на 2026-10-24. **MVP завершён и принят для тестового использования.**

## Назначение и модель

Equo — учёт совместных расходов и взаиморасчётов. Основной путь:
регистрация → активация и вход → приглашение и Connect → общий расход
с равными долями → баланс и история → исправление расхода или ручной перевод.

Transfer — источник истины баланса, Debt — корень агрегата расхода;
Connect постоянный и неориентированный. Денежные единицы, округление, права,
история и retention определены в [бизнес-правилах](business-rules/business-rules.md),
[модели данных](data-model/entities.md), [HTTP-контрактах](api/http-contracts.md)
и [ADR](adr/architecture-decisions.md). Этот контекст не заменяет требования.

Приложение — модульный монолит: Symfony API, Nuxt frontend, PostgreSQL, Redis,
RabbitMQ, email worker, retention scheduler и Nginx. Локальный запуск — WSL/Linux
и Docker Compose; команды находятся в [README](../README.md).

| `MVP-SC-015—016` | История операций и ручные переводы |
| `MVP-SC-019—022` | Надёжная доставка email, безопасность, инварианты/конкурентность и retention |

активация) и `DR-B-010` (physical retention cleanup) закрыты реализацией этапов
6/7; их отметки исправлены до удаления завершённого плана.

- Стенд: https://equo.16-16-120-166.sslip.io/; HTTPS и Brevo настроены.

- Два npm advisory временно приняты владельцем. `DR-E7-060` остаётся

После приёмки MVP выполнена `MT-001`: минимальная длина пароля снижена до
8 Unicode code points для регистрации, смены и сброса. Нормативная политика —
BR-USR-009; результаты технической проверки — в записи задачи в [бэклоге](backlog.md).
Развёрнуто 2026-10-22; отдельная приёмка владельцем пока не выполнялась.

19 октября 2026 года технически завершена `MT-002`: на главной для
авторизованного пользователя показаны две независимые суммы задолженности
и пять последних расходов; технический блок API connection удалён.
Полный quality gate, включая 27 browser E2E, пройден. Результат и границы
приёмки указаны в [бэклоге](backlog.md). Развёрнуто 2026-10-22; отдельная
приёмка владельцем пока не выполнялась.

19 октября 2026 года технически завершена `MT-003`: по ссылке активации
пользователь явно нажимает «Активировать и войти», после чего создаётся новая
сессия и открывается профиль без повторного ввода пароля. Простое открытие
ссылки аккаунт не активирует. Контракт, бизнес-правила и ADR-020 обновлены;
доработка с явным подтверждением прошла полный `make check-full`, включая
27 browser E2E.
Развёрнуто 2026-10-22; отдельная приёмка владельцем пока не выполнялась.

21 октября 2026 года технически завершена `MT-004`: активный пользователь
автоматически принимает ссылку и видит результат на странице Connect; гость
проходит вход или регистрацию, а новый пользователь продолжает принятие после
явной активации аккаунта. `make check-full` прошёл с 29 browser E2E; детали
реализации и результаты отражены в [бэклоге](backlog.md). Развёрнуто
2026-10-22; отдельная приёмка владельцем пока не выполнялась.

22 октября 2026 года технически реализована `MT-005`: сообщение о лимите входа
показывает живой отсчёт по серверному `Retry-After`, вычисляя оставшееся время
от срока окончания ожидания. Полный `make check-full` прошёл: 690 backend tests /
8 448 assertions и 30 browser E2E. Функциональное тестирование владельцем
отложено; развёрнуто на целевом стенде 2026-10-22.

24 октября 2026 года технически завершена `MT-006`: принятие нового
приглашения при уже существующем Connect не создаёт дубль и показывает
информационное сообщение с именем второй стороны. Новый Connect, заранее
существующая пара и идемпотентное подтверждение потерянного ответа различаются
явным результатом API. Полный GitHub Actions gate прошёл: 693 backend tests /
8 465 assertions и 30 browser E2E. Доработка ещё не развёрнута на AWS;
отдельная функциональная проверка владельцем не выполнялась.

24 октября 2026 года технически завершён Should-сценарий `SH-006`
(`MVP-SC-006`): пользователь может изменить отображаемое имя и подтвердить
новый email одноразовой ссылкой. Новый адрес не попадает в URL, повторно
проверяется на уникальность при применении и становится логином без отзыва
существующих sessions. Локальные профильные проверки и 31 browser E2E прошли;
итоговый полный GitHub Actions gate будет выполнен для всей накопительной ветки.

24 октября 2026 года технически завершён Should-сценарий `SH-007`
(`MVP-SC-007`): пользователь может деактивировать аккаунт с подтверждением
текущим паролем и позднее реактивировать его через существующую ссылку активации.
Деактивация атомарно отзывает refresh sessions и немедленно блокирует финансовые
команды, сохраняя Connect, историю и баланс для других сторон. Реактивация создаёт
новую session; старые не восстанавливаются. Профильные backend/frontend проверки,
31 существующий browser E2E и отдельный новый lifecycle E2E прошли; итоговый
полный GitHub Actions gate будет выполнен для всей накопительной ветки.

25 октября 2026 года технически завершён Should-сценарий `SH-014`
(`MVP-SC-014`): автор может необратимо мягко удалить расход с защитой
актуальным ETag. Debt и автоматические доли выключаются атомарно, состав и
ручные платежи сохраняются; расход исчезает из списка, оставаясь доступным
прежним участникам по прямой ссылке только для чтения. Профильные backend и
frontend проверки и изолированный lifecycle browser E2E прошли; итоговый полный
GitHub Actions gate будет выполнен для всей накопительной ветки.

25 октября 2026 года технически завершён Should-сценарий `SH-017`
(`MVP-SC-017`): автор может с защитой актуальным ETag исправить сумму или
направление своего активного ручного платежа между прежними сторонами Connect и
необратимо мягко удалить его. Удалённый платёж остаётся в истории, баланс и
version обновляются атомарно, прямые команды для автоматических долей запрещены.
Профильные backend/frontend проверки и изолированный lifecycle browser E2E
прошли; итоговый полный GitHub Actions gate будет выполнен для всей
накопительной ветки.

25 октября 2026 года технически завершён Later-сценарий `LT-010`
(`MVP-SC-010`): два разных активных текущих участника доступного неудалённого
